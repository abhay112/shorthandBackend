# Student User API Documentation

This guide covers every student-facing endpoint mounted under `/api/v1/user`.  
All routes require Firebase authentication (`Authorization: Bearer <id-token>`).  
Routes marked **Approved Only** also require the student to pass the `requireApproval` middleware (`isApproved === true`).

---

## Conventions

- **Success envelope**
  ```json
  {
    "success": true,
    "message": "Human readable status",
    "data": { /* endpoint specific payload */ }
  }
  ```

- **Error envelope**
  ```json
  {
    "success": false,
    "message": "What went wrong"
  }
  ```

- Unless stated otherwise, timestamps are ISO 8601 strings in UTC.

## 1. Profile & Status

### GET `/api/v1/user/profile`
- **Approval:** Not required  
- **Description:** Fetch the currently authenticated student's profile.  
- **Success Response (200)**
  ```json

    "success": true,
    "message": "Student profile retrieved successfully",
    "data": {
      "student": {

        "createdAt": "2024-05-01T09:00:00.000Z",
        "updatedAt": "2025-11-10T06:35:18.234Z"
      }
    }
  ```

## 3. Test Discovery (Approved Only)

### GET `/api/v1/user/tests/current`
- **Description:** Provides the current day’s prioritised tests.  
- **Success Response (200)**
  ```json
  {
    "success": true,
    "message": "Current test fetched successfully",
    "data": {
      "primaryTest": {
        "test": { "_id": "651a...", "title": "Court Reporting Drill", "duration": 300 },
        "priority": 9,
        "canTake": true,
        "isBlocked": false,
        "blockReason": null,
        "availableFrom": "2025-11-10T09:00:00.000Z",
        "availableUntil": "2025-11-10T17:00:00.000Z"
      },
      "allTestsForToday": [
        {
          "test": { "_id": "651a...", "title": "Court Reporting Drill" },
          "priority": 9,
          "canTake": true,
          "isBlocked": false
        },
        {
          "test": { "_id": "651b...", "title": "Speed Accuracy Practice" },
          "priority": 7,
          "canTake": false,
          "isBlocked": true,
          "blockReason": "Under review"
        }
      ]
    }
  }
  ```

### GET `/api/v1/user/tests/upcoming`
- **Query Parameters:**  
  - `days` (optional, default backend controlled)  
  - `limit` (optional)  
- **Success Response (200)**
  ```json
  {
    "success": true,
    "message": "Upcoming tests fetched successfully",
    "data": {
      "upcomingTests": [
        {
          "date": "2025-11-11",
          "tests": [
            {
              "_id": "65b2...",
              "title": "Dictation Drill",
              "priority": 8,
              "availableFrom": "2025-11-11T09:00:00.000Z",
              "availableUntil": "2025-11-11T17:00:00.000Z"
            }
          ]
        }
      ]
    }
  }
  ```

- **Description:** Check if the student can take the specified test right now.  
  Calling this endpoint **consumes an attempt immediately** by reserving it for the student.
- **Success Response (200)**
  ```json
  {
    "success": true,
    "message": "Test access checked successfully",
    "data": {
      "accessCheck": {
        "canTake": true,
        "remainingAttempts": 2,
        "attemptNumber": 2,
        "reservationSessionId": "f3b978ea-0d9b-4e09-9e46-8a6d1fa49f7c"
      }
    }
  }
  ```
  > Only call `/access` when the student is ready to begin; repeated calls will eventually exhaust the allowed retakes.

### GET `/api/v1/user/test/current` (Legacy)
- Same payload as `/tests/current`; provided for backwards compatibility.

## 8. Error Handling Summary

| HTTP Code | When it appears | Example Message |
|-----------|-----------------|-----------------|
| `400 Bad Request` | Missing fields, invalid IDs/JSON, malformed metrics | `"Missing required fields: wpm, accuracy"` |
| `401 Unauthorized` | Missing/invalid auth token | `"Unauthorized"` |
| `403 Forbidden` | Student not approved for approved-only routes | `"Student approval required"` |
| `404 Not Found` | Test/result/session not found or not accessible | `"Result not found or you do not have access to it"` |
| `410 Gone` | Legacy submission endpoint | `"This endpoint is deprecated. Please use the new test session endpoints."` |
| `429 Too Many Requests` | Rate limit protection (if enabled) | `"Too many requests"` |
| `500 Internal Server Error` | Unexpected failures | `"Internal server error"` |

## 9. Frontend Prompt Template

Use the following snippet when instructing Cursor/AI tools:

> Implement the Shorthnd LMS student dashboard using these APIs (all require `Authorization: Bearer <firebase-id-token>` and approved routes require `isApproved`).  
> - `GET /api/v1/user/tests/current` → `{ primaryTest, allTestsForToday[] }`  
> - `GET /api/v1/user/tests/upcoming` → grouped schedule  
> - `GET /api/v1/user/tests/{testId}/access` → **consumes** an attempt and returns `{ remainingAttempts, attemptNumber, reservationSessionId }`  
> - `POST /api/v1/user/tests/{testId}/start` → `{ sessionId, test, content, attemptNumber, remainingAttempts, timeExpires }`  
> - `POST /api/v1/user/sessions/{sessionId}/end` → `{ result }` (see metrics schema)  
> - `GET /api/v1/user/results?page=&limit=` → paginated attempts  
> - `GET /api/v1/user/results/{resultId}` → detail view  
> - `GET /api/v1/user/rankings` and `/batches/{batchId}/leaderboard` → charts  
> Persist session ID, handle 401/403 redirect, surface 410 deprecation warnings, and respect availability windows.
